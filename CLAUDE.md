# CLAUDE.md

Firefox add-on + Chrome extension (one MV3 codebase) that adds **Mark as watched** to YouTube:
an item in the video ⋮ menu and a button under the player. Clicking records the video as 100%
watched in the user's YouTube history. Firefox is the primary target.

## Layout

- `manifest.json`: single MV3 manifest. Firefox-only keys live in `browser_specific_settings`;
  `scripts/build.sh` strips them (and adds `minimum_chrome_version`) for the Chrome copy.
- `src/content.js`: all logic, no build step, no dependencies. Runs in the page **MAIN world**.
- `src/styles.css`: injected via a separate, isolated-world content_scripts entry.
- `icons/`: generated by `node scripts/make-icons.mjs` (pure Node PNG writer, no deps).
- `scripts/build.sh`: writes `dist/firefox/`, `dist/chrome/` (unpacked) and both store zips.
- `scripts/publish.sh firefox|chrome|all`: build + lint + upload, using credentials from `.env`.
- `docs/PUBLISHING.md`: store upload guide, written in **Vietnamese**.

## Commands

```bash
./scripts/build.sh                                   # package into dist/
npx web-ext lint --source-dir dist/firefox           # must stay at 0 errors / 0 warnings
node --check src/content.js                          # quick syntax check
npx web-ext run --source-dir . --url https://www.youtube.com   # run in Firefox
./scripts/publish.sh all                             # publish current version to both stores
```

## How marking works (`src/content.js`)

1. Get a player response with `playbackTracking`, in this order:
   live `#movie_player.getPlayerResponse()` (current video only), then the server-rendered
   `/watch?v=…` HTML (`ytInitialPlayerResponse`, parsed with a string-aware brace matcher),
   then `/youtubei/v1/player` (signed in, then anonymous). **Do not move the API back to
   first place:** for signed-in users it returns `400 Precondition check failed`, because
   it wants a PoToken.
2. Send `videostatsPlaybackUrl` (start) and `videostatsWatchtimeUrl` with `st=0`, `et=cmt=len`,
   `final=1`. The host is rewritten from `s.youtube.com` to `www.youtube.com`, so the request is
   same-origin and carries cookies.
3. On the watch page, pause the player first. Otherwise its own watchtime pings overwrite ours.

## Gotchas

- **Trusted Types**: YouTube enforces them, so `innerHTML` throws. Build DOM with
  `createElement` / `createElementNS`.
- **MAIN world** is required for `ytcfg`, the player API and same-origin cookies. That needs
  Firefox 128+ and Chrome 111+. `browser.*` / `chrome.*` APIs are not available there.
- The ⋮ popup is a single reused `ytd-popup-container` dropdown, filled asynchronously.
  The script remembers the last clicked card (`targetFromClick`) and polls (`watchMenu`)
  to inject or remove `.maw-menu-item`. It supports both the old
  `tp-yt-paper-listbox` menus and the new `yt-list-view-model` menus.
- The watch button is inserted into `ytd-watch-metadata #actions ytd-menu-renderer`, before the
  `yt-icon-button#button` / `yt-button-shape` overflow button, and re-checked every second.
- `window.__markAsWatchedLoaded` guards against double injection. After reloading or
  reinstalling the add-on, **reload the YouTube tab**.
- UI strings are in the `T` table: Vietnamese if `<html lang>` starts with `vi`, otherwise English.

## Testing

No automated tests. To check the UI, open YouTube in the browser pane and paste the script via
`javascript_tool`. You can't fetch it from localhost, because YouTube's CSP blocks that.
Without a signed-in account, only the UI and the anonymous request paths can be verified;
the actual history write must be checked by the user in a signed-in browser.

## Releases

1. Bump `version` in `manifest.json`. The stores reject a version that was already uploaded.
2. Run `./scripts/build.sh` and lint, commit `chore: release X.Y.Z`, tag `vX.Y.Z`,
   then `git push --follow-tags`.
3. Run `gh release create vX.Y.Z dist/*.zip`, and optionally `./scripts/publish.sh all`.

`.env` holds the AMO JWT and Chrome Web Store OAuth secrets. It is gitignored: never read it,
print it or commit it. `.env.example` lists the variable names.

Commits follow Conventional Commits (`feat:`, `docs:`, `chore:` …).
