# CLAUDE.md

Firefox add-on + Chrome extension (one MV3 codebase) that adds **Mark as watched** to YouTube:
an item in the video ⋮ menu and a button under the player. Clicking records the video as 100%
watched in the user's YouTube history. Firefox is the primary target.
It also adds a trash button to rows of playlists the user owns, a blue bar on thumbnails of
videos in Watch later (WL), "Remove from Watch later" in the ⋮ menu of those videos, Undo for
removals, dimming/hiding of watched videos, Shift+W / Shift+L shortcuts, Shift+click
multi-select with a bottom toolbar, and a settings page.

## Playlists and Watch later (`src/content.js`, sections 3 and 4)

- Writes use `/youtubei/v1/browse/edit_playlist` via `innertube()`: SAPISIDHASH + cookies are
  enough here (no PoToken). WL removal uses `ACTION_REMOVE_VIDEO_BY_VIDEO_ID` + `removedVideoId`.
- Trash button: shown only if the row's renderer data (`el.data`) has a `playlistEditEndpoint`
  with a remove action in its ⋮ menu, i.e. the playlist is editable. That endpoint is sent as is.
  Removed rows are hidden (`.maw-removed`) and keyed by `setVideoId`, since Polymer recycles rows.
- WL membership: the whole WL list is loaded via `browse` `VLWL` + continuations into
  `watchLater.ids`, refreshed every 5 min on navigation/focus. It is updated locally on our own
  removals and on clicks of the native "Save to Watch later" item, and reloaded 2 s after
  clicks on other WL toggles (thumbnail hover button, Save dialog). Blue bars are skipped on
  `list=WL` pages.
- Undo (toast button): WL → add back with `ACTION_ADD_VIDEO`. Playlist rows → add back, read the
  new `setVideoId` from `playlistEditVideoAddedResultData`, then `ACTION_MOVE_VIDEO_BEFORE`
  (`movedSetVideoIdSuccessor`, or `ACTION_MOVE_VIDEO_AFTER` + predecessor for the last row). The
  hidden row is shown again and its renderer data patched to the new `setVideoId`.

## Cards, shortcuts, multi-select (`src/content.js`, sections 5 to 7)

- `scanCards()` is the one pass over all `CARD_SELECTOR` cards (WL bar, dim/hide, selection
  outline). It runs from a throttled `MutationObserver` (200 ms) and the 1 s `tick()`. Cards nest
  (`ytd-rich-item-renderer > yt-lockup-view-model`), so dim/select only `outerCard()`, otherwise
  opacities multiply.
- "Watched" = width of the red progress bar on the thumbnail (`#progress` / `*WatchedProgressBarSegment`),
  falling back to `percentDurationWatched` in the renderer data. Only the outer page kinds in
  `pageKind()` are dimmed; on /watch only the sidebar, never the playlist panel.
- Shift+click is taken over on `window` in the capture phase (before YouTube and our own handlers),
  plus Shift+mousedown is prevented so it doesn't start a text selection. Selection is keyed by
  video ID, since cards get recycled.

## Settings

- `src/settings.js`: defaults + load/save in `storage.sync`, shared by the options page and the
  bridge. **`content.js` keeps its own copy of the defaults**: keep both in sync.
- `src/settings-bridge.js` (isolated world, same entry as the CSS) writes the settings as JSON into
  `<html data-maw-settings>` and fires `maw-settings`; `content.js` (MAIN world) reads them in
  `readSettings()`. Only strings cross: objects don't cross worlds in Firefox.
- `src/options.html`/`options.js`: the options page (`options_ui`, opens in a tab). It also shows
  whether the YouTube host permission is granted, with Allow / "Reload YouTube tabs" buttons.
  Changes are saved on input (debounced 250 ms because of `storage.sync` quotas) and reach open
  YouTube tabs live through `storage.onChanged`.

## Layout

- `manifest.json`: single MV3 manifest. Firefox-only keys live in `browser_specific_settings`;
  `scripts/build.sh` strips them (and adds `minimum_chrome_version`) for the Chrome copy.
  It also turns `background.scripts` (Firefox event page) into `background.service_worker` for Chrome.
- `src/content.js`: all logic, no build step, no dependencies. Runs in the page **MAIN world**.
- `src/styles.css`: injected via a separate, isolated-world content_scripts entry, together with
  `src/settings.js` + `src/settings-bridge.js` (see Settings).
- `src/background.js`: only watches the YouTube host permission.
  In MV3 the user can withhold it (Firefox may not grant it, e.g. after switching from a
  temporary add-on to the AMO build), and then the content scripts silently never run. Missing
  permission → red "!" badge on the toolbar button, and the options page opens on
  install/update. The toolbar button and the page's Allow button call `permissions.request()`,
  which in Firefox must be called synchronously inside the user action (no `await` before it).
  The toolbar button then opens the options page.
- `icons/`: generated by `node scripts/make-icons.mjs` (pure Node PNG writer, no deps).
- `scripts/build.sh`: writes `dist/firefox/`, `dist/chrome/` (unpacked) and both store zips.
- `scripts/publish.sh firefox|chrome|all`: build + lint + upload, using credentials from `.env`.
- `docs/PUBLISHING.md`: store upload guide, written in **Vietnamese**.

## Commands

```bash
./scripts/build.sh                                   # package into dist/
npx web-ext lint --source-dir dist/firefox           # must stay at 0 errors / 0 warnings
node --check src/content.js                          # quick syntax check
npx web-ext run --source-dir . --url https://www.youtube.com   # run in Firefox
./scripts/publish.sh all                             # publish current version to both stores
```

## How marking works (`src/content.js`)

1. Get a player response with `playbackTracking`, in this order:
   live `#movie_player.getPlayerResponse()` (current video only), then the server-rendered
   `/watch?v=…` HTML (`ytInitialPlayerResponse`, parsed with a string-aware brace matcher),
   then `/youtubei/v1/player` (signed in, then anonymous). **Do not move the API back to
   first place:** for signed-in users it returns `400 Precondition check failed`, because
   it wants a PoToken.
2. Send `videostatsPlaybackUrl` (start) and `videostatsWatchtimeUrl` with `st=0`, `et=cmt=len`,
   `final=1`. The host is rewritten from `s.youtube.com` to `www.youtube.com`, so the request is
   same-origin and carries cookies.
3. On the watch page, pause the player first. Otherwise its own watchtime pings overwrite ours.

## Gotchas

- **Trusted Types**: YouTube enforces them, so `innerHTML` throws. Build DOM with
  `createElement` / `createElementNS`.
- **MAIN world** is required for `ytcfg`, the player API and same-origin cookies. That needs
  Firefox 128+ and Chrome 111+. `browser.*` / `chrome.*` APIs are not available there.
- The ⋮ popup is a single reused `ytd-popup-container` dropdown, filled asynchronously.
  The script remembers the last clicked card (`targetFromClick`) and polls (`watchMenu`)
  to inject or remove `.maw-menu-item`. It supports both the old
  `tp-yt-paper-listbox` menus and the new `yt-list-view-model` menus.
- The watch button is inserted into `ytd-watch-metadata #actions ytd-menu-renderer`, before the
  `yt-icon-button#button` / `yt-button-shape` overflow button, and re-checked every second.
- `window.__markAsWatchedLoaded` guards against double injection. After reloading or
  reinstalling the add-on, **reload the YouTube tab**.
- UI strings are in the `T` table: Vietnamese if `<html lang>` starts with `vi`, otherwise English.

## Testing

No automated tests. To check the UI, open YouTube in the browser pane and paste the script via
`javascript_tool`. You can't fetch it from localhost, because YouTube's CSP blocks that.
Without a signed-in account, only the UI and the anonymous request paths can be verified;
the actual history write must be checked by the user in a signed-in browser.

## Releases

1. Bump `version` in `manifest.json`. The stores reject a version that was already uploaded.
2. Run `./scripts/build.sh` and lint, commit `chore: release X.Y.Z`, tag it with an annotated
   tag (`git tag -a vX.Y.Z -m vX.Y.Z`: `--follow-tags` skips lightweight tags), then
   `git push --follow-tags`.
3. Run `gh release create vX.Y.Z dist/*.zip`, then `./scripts/publish.sh firefox`. The Chrome
   Web Store API variables in `.env` are not set up, so Chrome is uploaded by hand in the dashboard.

`.env` holds the AMO JWT and Chrome Web Store OAuth secrets. It is gitignored: never read it,
print it or commit it. `.env.example` lists the variable names.

Commits follow Conventional Commits (`feat:`, `docs:`, `chore:` …).
